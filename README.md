# PolarDRL — Reproducibility Codebase

Deep reinforcement learning for polarization-disagreement minimization via sequential link recommendation. Foundation paper: Zhu et al. 2021, *Minimizing Polarization and Disagreement in Social Networks via Link Recommendation* (NeurIPS 2021).

This repo covers Task 3 of the project (reproducibility & baselines) — see the sibling Obsidian vault at `../PolarDRL/PaperGuidelines.md` for the full project scope, and `../PolarDRL/Concepts/` for reference notes on every concept these modules implement (FJ model, P-D index, SPGREEDY, FASTGREEDY, COMP).

## Status

Baselines complete and validated: `fj_model.py`, `pd_index.py`, `spgreedy.py` (exact greedy,
Algorithm 1), and `fastgreedy.py` (COMP + FASTGREEDY, Algorithms 2-3) are all implemented.
SPGREEDY matches brute-force Optimum across the full grid (4 small networks x 3 opinion
distributions x k=1..8); FASTGREEDY tracks SPGREEDY within the paper's reported band and
reproduces the Table 1 GrQc row. See `paper_results/README.md` for the full validation writeup,
including two bugs caught and fixed along the way (a Karate loader weighting bug, and a JL
projection-dimension cap needed to keep FASTGREEDY within this machine's RAM). Next: commit, then
Phase 4 (DRL agent) uses these as the benchmark baselines.

## Environment

### Container usage

`datasets/raw/` (network-fetched, large) and `results/` (generated by the reproduction scripts)
are gitignored and not baked into the image — mount them as volumes so downloaded data and
reproduction outputs persist across runs instead of being re-fetched or lost every time.

**On Windows with Docker Desktop:** the `Containerfile` uses only standard Dockerfile syntax (no
Podman-specific instructions), so `docker build`/`docker run` work the same way under Docker
Desktop's default Linux-containers mode (WSL2 backend) — just use your shell's path syntax for the
volume mount (no `:Z` SELinux flag needed; Windows has none):

```powershell
# PowerShell
docker build -t polardrl -f Containerfile .
docker run --rm polardrl

mkdir datasets\raw, results -Force
docker run --rm `
  -v "${PWD}\datasets\raw:/app/datasets/raw" `
  -v "${PWD}\results:/app/results" `
  polardrl `
  bash -c "bash datasets/download.sh && python scripts/reproduce_fig1.py"
```

```cmd
:: cmd.exe
docker build -t polardrl -f Containerfile .
docker run --rm polardrl

mkdir datasets\raw results
docker run --rm ^
  -v "%cd%\datasets\raw:/app/datasets/raw" ^
  -v "%cd%\results:/app/results" ^
  polardrl ^
  bash -c "bash datasets/download.sh && python scripts/reproduce_fig1.py"
```

This machine (Fedora) has **Podman**, not Docker Engine — the `Containerfile` uses standard Docker
syntax and works with either:

```bash
podman build -t polardrl -f Containerfile .
podman run --rm polardrl                      # runs the test suite (7 tests, no network needed)
```

**On Linux/Mac (or this project's own dev machine, Fedora with Podman):**

```bash
mkdir -p datasets/raw results
podman run --rm \
  -v ./datasets/raw:/app/datasets/raw:Z \
  -v ./results:/app/results:Z \
  polardrl \
  bash -c "bash datasets/download.sh && python scripts/reproduce_fig1.py"
```

(`:Z` relabels the volume for SELinux under Podman on Fedora; drop it if not needed. Swap `podman`
for `docker` if using Docker on Linux/Mac instead.)

Local (non-container) development uses [`uv`](https://docs.astral.sh/uv/), already installed:

```bash
uv venv --python 3.11        # system Python is 3.14, too new for some DRL libs (PyTorch/JAX) — pin 3.11
source .venv/bin/activate
uv pip install -e .
pytest
```

## Layout

```
src/polardrl/
  fj_model.py      Friedkin-Johnsen opinion-equilibrium computation
  pd_index.py      Polarization-Disagreement index (the objective)
  spgreedy.py      Exact greedy baseline (Algorithm 1)
  fastgreedy.py    Fast approximate baseline (Algorithms 2-3)
datasets/          Network data + fetch instructions (raw data gitignored)
tests/             pytest suite, starting with a hand-checkable P-D index fixture
```

## Reproducing the paper's results

1. `fj_model.py` and `pd_index.py` — validated against `tests/test_pd_index.py`'s hand-computed fixture (closed-form identities match exactly).
2. `spgreedy.py` — run on the 4 small networks (Karate, Dolphins, Netscience, Diseasome) with k=1..8: Δ I(G) matches brute-force Optimum everywhere (`scripts/reproduce_fig1.py`, reproduces Figure 1); GrQc at k=50 lands within 8% of the paper's Table 1 number (`scripts/reproduce_table1.py`).
3. `fastgreedy.py` — COMP's estimate tracks exact marginal gain within the paper's Theorem 6.1 bound; FASTGREEDY tracks SPGREEDY within the paper's reported ~1% band (both scripts above extended to cover it).
4. Baselines are verified — this is now the benchmark for the DRL agent (Phase 4, not yet started).

Run both reproduction scripts (needs downloaded datasets — see "Container usage" above, or run
`datasets/download.sh` directly for local dev):

```bash
python scripts/reproduce_fig1.py     # Figure 1: 4 networks x 3 distributions x k=1..8
python scripts/reproduce_table1.py   # Table 1: GrQc row, k=50
```
